## Findings

### 1. [medium] AsOfParityTest: about a fifth of the generated list requests compare an empty page with an empty page
AsOfParityTest.java:74-84 uses fixed filter values per type, and nothing asserts that an answer has rows. The probe run found 25 of the 135 list requests empty live:
- `regionName:contains:a` on all six lists;
- customers `successPocUserId`/`collectionPocUserId:isNotEmpty`, `creditBalance:gt:0`, `phone`/`email`/`address:contains:a`;
- invoices `paidAmount:gt:0`, `invoiceNumber:contains:a`;
- promises `paymentId:isNotEmpty`, `status:neq:OPEN`, `fulfilledAmount:gt:0`, `statusOverridden:eq:true`;
- payments `creditApplied:gt:0`;
- and others.

For these columns the test cannot see a broken as-of predicate that drops rows. Several of them are the risky version-root paths: the seat subquery, the promise link subquery, and the region join from a version root. CF-13 parity is only proven for the ~80% of columns that happen to match rows.
Fix: take each filter value from the captured live data (for example, the first live row's value for that column), or assert that each filterable column has at least one non-empty probe.

### 2. [low] DocumentDto.canDownload and EmailDto.canOpenRecord stay true in historical answers
The slice says "Every DTO flag ANDs !historical", and §5.7.17 says documents' "toDto flags false". Where the code differs:
- DocumentService.java:257 sets `canDownload = !d.isDeleted()`, so it is true at T for any file not deleted since. AsOfTabsTest.java:97 asserts true at D3.
- EmailViews.java:104 passes `canSeeRecord`, which is true at T.

AsOfParityTest's "every can* flag must be off" check (FLAG regex at :57) never runs over the documents or emails tabs, so nothing enforces the rule there. canDownload is a logged deviation with a sensible reason: download is live and IGNORED. Either record it as an accepted exception to D14 or AND it with !AsOf.active().

### 3. [low] Audit of a PRODUCT as of a date before it existed returns 200 [] instead of 404
AuditController.java:120-132 has no PRODUCT case (`default -> {}`), so `ensureCallerCanSee` never reads the product. Products are versioned. So `GET /api/audit?entityType=PRODUCT&entityId=<created after T>&asOf=T` returns 200 with an empty list, while §5.7.17 says "no version at T gives 404". The live behaviour for an unknown product is also 200 [] (pre-existing), so the impact is small.
Fix: add `case "PRODUCT" -> readOrGone(id, () -> records.find(Product.class, id).orElseThrow(NotFound), productRepository::existsById)`.

### 4. [low] As of a date, derived audit entries carry today's state
AuditTimelineService.java:73-77 runs the whole assembly, including the primary record lookup, under LiveReadGuard.allow. The gotcha asks for "only related-record discovery". So `derived()` builds entries from live entities:
- CUSTOMER_CREATED's after-JSON has today's name, phone and email (:188-190);
- DISPUTE_DENIED is added from the current status (:222-228).

These entries then pass the createdAt cut. This only affects records that have no audit row (legacy or seeded data), and it is logged as "derived audit labels are current". But the values are shown in an as-of trail as if they were the state at T.
