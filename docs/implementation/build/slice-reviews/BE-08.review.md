## Findings

### LOW-1: a failed first baseline whose chunks all committed leaves `started_at` null ("no lower bound") for good
- Location: `backend/src/main/java/com/geneinvoice/history/HistoryBaseline.java:72-79,125`
- `started_at` is written only by the outer `held` transaction, at its commit (`:77`), and only when *this* run copied something (`startedAt[0]` is set in a chunk at `:125`). The chunks are REQUIRES_NEW and commit on their own.
- When the outer transaction fails after the chunks have committed, `baseline_completed_at` stays null. For example, a Postgres `idle_in_transaction_session_timeout` kills the outer connection, which sits idle holding the meta lock for the whole baseline.
- The next boot is then a first run again, but finds nothing missing. So it sets `baseline_completed_at` and leaves `started_at` null.
- `HistoryRange.historyStartsOn()` then answers empty, which means no lower bound. Once BE-09a wires it, an as-of before the real start is answered from nonexistent versions (empty lists) instead of 400 `AS_OF_BEFORE_HISTORY`. That breaks D9/Q3 ("not approximated").
- `aFailingBaselineLetsStartupCarryOn` injects its failure into the first chunk of the first type, so it never covers a failure after chunks have committed.
- Fix: persist `started_at` in its own committed transaction when the first chunk of a first run is pinned (only if null), or derive it on a first run from `min(valid_from)` of SCHEMA-origin versions when this run copied nothing.

### LOW-2: `customer_region_moves.moved_at` is not the move's history instant
- Location: `backend/src/main/java/com/geneinvoice/region/CustomerRegionMoveService.java:135`
- `movedAt(clock.instant())` is read at step 13. It is not truncated to microseconds. Every moved version's `valid_from` is the writer's instant, which is bound later, at commit (§5.7.4).
- In production the log row is therefore slightly earlier than the versions. For points p with moved_at <= p < t, the log (D8 `moved_at <= p`, which the BE-15 cool-down also reads) says "moved" while every version still shows the old region.
- The test cannot see this: `theCustomerAndEveryRecordOfItMoveInOneGo` and `historyShows...` freeze MovableClock, so both instants equal `at`.
- Fix: at least `truncatedTo(MICROS)`. Better, stamp `moved_at` from the transaction's history instant; `HistoryTransactions.txId` and `needsInstant` arrive in BE-11.

### LOW-3: the rollback test covers only a veto raised before anything is written
- Location: `backend/src/test/java/com/geneinvoice/region/CustomerRegionMoveTest.java` (`aParticipantsRefusalRollsTheWholeMoveBack`); `TestMoveParticipant.afterCustomerMoved` can never throw.
- Every refusal the test covers, the veto included, happens before step 11. At that point no native update, touch or move row exists yet, so "everything is rolled back" is trivially true.
- Nothing proves that a failure after the native updates and `historyTracker.touch` (an `afterCustomerMoved` participant throwing, as the BE-12 and BE-15 participants can) leaves no moved rows, versions or move row.
- Fix: let `TestMoveParticipant` throw in `afterCustomerMoved` too, and assert `state()` is unchanged.
