## Findings (most severe first)

### M1 (medium) A preview with evaluateAs=OWNER fills in POC names using the owner's POC_VIEW, for a caller who may not hold it
- RulePreviewService.java:154-155 builds the whole per-record preview, `actions(rule, ruleId, chosen)` included, inside `as(asOwner, ...)`, which is `runAs.call(owner, ...)` (line 227).
- `RecordContexts.load` (RecordContexts.java:78) therefore builds `PlaceholderValues(values, scopeResolver.canSeePoc())` with the owner's rights.
- `PlaceholderRenderer.render` (PlaceholderRenderer.java:66) then fills in `{{Customer.CollectionPoc}}`, `{{Invoice.SalesPoc}}`, `{{...PocEmail}}`, and the promise preview's `collectionPoc` name, whenever the owner holds POC_VIEW.
- The caller only needs AUTOMATION_ADMIN plus sight of the record (`labelFor`). PC-7's rule is that an administrator cannot read records through the owner's rights, and the implementer's report says POC names are hidden from anyone without POC_VIEW. This path breaks both.
- PreviewTest's `adam` (AUTOMATION_ADMIN, INVOICE_VIEW, no POC_VIEW) is exactly this caller, but the test's rule has no POC placeholder, so nothing catches it.
- Fix: in OWNER mode, render the record's actions as the caller, or AND `canSeePoc` with the caller's. Add a PreviewTest case with `{{Customer.CollectionPoc}}` and evaluateAs=OWNER for adam.

### L1 (low) A PUT that leaves out `enabled` turns a disabled rule on, and a PUT that leaves out `version` skips the stale check
- RuleValidator.java:119 reads `req.enabled() == null || req.enabled()`. RuleService.update:219 then calls `r.setEnabled(v.definition().enabled())` and sets `activeSince`.
- So a PUT body without `enabled` silently turns on a disabled rule, which then acts. `maxRecordsPerRun` also falls back to the default (1000) when it is left out.
- RuleService.requireVersion:299-303 skips the check when `version` is null, so the §6.14 "409 stale" check is optional.
- Fix: on update, a null `enabled` keeps `r.isEnabled()`. Either require `version`, or document that it is optional.

### L2 (low) The CREATE_PROMISE check-and-prepare step skips the §5.10.5 assignability check on a named Collection POC
- CreatePromiseHandler.collectionPoc (CreatePromiseHandler.java, the USER branch) only filters on `User::isActive`.
- It never calls `pocService.requireAssignable(u, COLLECTION, rc.regionId())`, which §5.10.5 requires for "USER -> requireAssignable(u, COLLECTION, region)". It does not run the user through VisibilityProbe either.
- A preview (and later `perform`, if BE-19 builds on `Prepared`) reports no problem for a person who holds no POC_ASSIGNABLE_COLLECTION, or no grant, in the record's region.
- Fix: call `requireAssignable` in `prepare` and add a problem on BadRequestException.

### L3 (low) The owner-view matches page sends back the owner's regions and locked filters
- RulePreviewService.matches:116-126 builds the page with `e.scope()`, which `scopeResolver.scope(...)` computed inside `runAs.call(owner, ...)`.
- `PageResponse.of(..., scope)` (PageResponse.java:30-31) serialises `scope.lockedFilters()`, `regionIds()` and `bookRegionIds()`. The caller therefore sees the owner's region ids and book regions, and for a BOOK owner a locked filter naming the owner.
- The page should describe the caller's view, not the owner's.
- Fix: build the page's scope as the caller, the same way `callerSees` does.

### L4 (low) Matches pages stop at 5,000 records, while totalElements counts them all
- RuleEvaluator.page:85-89 caps `upTo` at `TableQueryExecutor.BULK_ID_LIMIT` (5000), but `matches` reports `e.count()` as `totalElements`.
- For more than 5,000 matches (an invoice rule with a broad or empty condition), pages past id number 5000 come back empty, while `totalPages` says more exist.
- Fix: page by keyset or offset (setFirstResult) instead of loading the prefix. At least cap `totalElements` or return 400 past the limit.

## Checked and found correct (no finding)
- **Ownership (SC-2).** PUT and enable by a non-owner need AUTOMATION_ADMIN (403) and confirmation (400). The admin who confirms becomes the owner, with a revision and RULE_OWNERSHIP_TAKEN. Disable and delete are allowed to the owner or an admin without taking the rule over. Rights and regions are checked against the new owner.
- **Revisions.** One is written in the same transaction for create, update, enable, disable, delete and take-over.
- **Visibility (§5.10.10).**
  - Live list and summary: a Criteria predicate with EXISTS on the rule's regions or the owner's grants.
  - As of a date: checked in memory on the snapshot's regions, with the owner's grants today.
  - By id: 404 for a rule the caller may not see.
  - `regionIds` narrows the rules for everyone, administrators included.
- **Historical requests.** The list, detail and summary come from revisions, and every flag is false. The three previews evaluate the revision in force at the date (404 if the rule did not exist then) and return `record.actions = null` with `asOfNote`. Writes are refused (class @AsOfAware with no method annotation).
- **Preview.** It runs in a TransactionTemplate that is read-only and rolled back. In OWNER mode, sample and record carry only records the caller can see (Reach.GRANTED as the caller), and a hidden sample has no id, label or link.
- **Conditions.** Limits, paths, and a dry-run count that forces value coercion at save. AND-only trees give a `listLink`. The "not an update" warnings are in place.
- **New columns.** `paymentTerm` and `overdueAmount` are in the schemas. `overdueAmount` is a Temporal subquery, so it is correct as of a date, and AsOfParityTest picks it up from the schema.
- **Schema.** AutomationSchemaUpgrade widens all six enum columns. The new tables are plain JPA DDL; no existing table gains a NOT NULL column.
- **JPQL.** `nameTaken`, `latestAt`, `countFailed` and `findActiveStaffHolding` are valid on both H2 and Postgres.
- **Other wiring.** The seeding matches §4.1, and the classification tests and the ViewScope and AsOf inventories are updated. AuditController reads RULE trails through RuleService.get (visibility applies, and a deleted rule's trail stays readable).
