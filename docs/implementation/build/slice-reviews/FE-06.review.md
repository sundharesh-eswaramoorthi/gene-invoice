# FE-06 review (Tasks UI)

Definition of done re-run: `flutter analyze` 0 issues; `flutter test` 315/315 passed.

No critical or high findings. Scope/as-of checks passed: every task read goes through the dio
interceptor (regionIds/asOf), list/count/detail providers watch the scope and call checkAsOf,
every mutating control (New task, Edit, row moves, bulk) is closed while historical, create is
gated per region (hasIn(taskManage, regionId)), people search is record-scoped, the tab's
presence depends only on a synchronous privilege (G5, with a real test), /my-tasks bulk/export
are kept to "assigned to me" via actionFilters.

## medium — Customer Tasks-tab badge counts different tasks than the tab lists
- task_actions.dart:57-58 asks `GET /api/tasks/count?entityType=CUSTOMER&entityId=<id>` while
  tasks_tab.dart:49-51 lists by `customerId` (customer + its invoices' + payments' tasks, §5.9.5).
- A customer with 0 customer-level tasks and 3 open invoice tasks shows no badge / "0" over a tab
  listing 3 open tasks. Deferred to BE-12 as a contract change request rather than solved here.
- Fix: derive the customer badge from the same query as the tab (e.g. `/api/tasks/summary` with
  `customerId`, open + inProgress), or get §6.12 `/count` amended to accept `customerId` and use it.

## low — No way to move an IN_PROGRESS task back to OPEN
- task_models.dart:195-202: Reopen is offered only from DONE/CANCELLED; §5.9.2 allows
  IN_PROGRESS → OPEN (assignees may move OPEN ↔ IN_PROGRESS). A task started by mistake can only
  be finished or cancelled.

## low — Due-date picker asserts for a due date more than 5 years out
- task_form_dialog.dart:85-91: `initialDate = _due`, `lastDate = today + 5y`; editing a task whose
  dueDate is later than that (e.g. created by a rule with a large offset) trips showDatePicker's
  `initialDate <= lastDate` assertion. Use `lastDate: max(_due, today+5y)`.
