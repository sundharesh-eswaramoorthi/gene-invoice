## MEDIUM: shape tests do not check column type or length for TEXT columns, so a version TEXT column can silently become varchar(255)
- Location:
  - T/history/VersionShapeTest.java:120-126 and :255-265: sizes come from `@Column.length()`, which defaults to 255 when absent; `columnDefinition` and `@Lob` are ignored.
  - VersionTablesHaveNoConstraintsTest checks no column types except enum columns.
- Probe: remove `@Lob ... columnDefinition = "TEXT"` from `DisputeVersion.proposedChangeJson` and from `InvoiceVersion.itemsJson`. All 16 history tests still pass.
  - The live `proposed_change_json` is TEXT; the version becomes varchar(255).
  - `items_json` is not a live column, so nothing checks it at all.
- Impact once BE-07 writes versions:
  - An invoice with about 3 or more lines (around 80 characters of JSON per line), or a long proposed change, would fail its version INSERT inside before-completion.
  - §5.7.6 does not catch database errors, so the user's own save would roll back. This breaks D3 rule 5 ("trivially safe") and §3.5 rule 2.
- Fix: compare physical columns live vs version through `information_schema.columns` (DATA_TYPE, CHARACTER_MAXIMUM_LENGTH, NUMERIC_PRECISION/SCALE), and assert `INVOICE_VERSIONS.ITEMS_JSON` is `CHARACTER LARGE OBJECT`.
