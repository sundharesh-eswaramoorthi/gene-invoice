## Findings

### 1. (low) `ClockReadGuardTest` does not catch a clock read through a zone constant or variable
- **Where:** `backend/src/test/java/com/geneinvoice/common/time/ClockReadGuardTest.java:28-37`.
- **Problem:** the "X.now(zone)" pattern is `\.\s*now\s*\(\s*(java\.time\.)?(ZoneOffset|ZoneId)\b`. It only matches when the argument text starts with `ZoneOffset` or `ZoneId`.
- **Result:** the guard passes all of these system-clock reads, which I checked by running the regexes:
  - `LocalDate.now(UTC)`, written with `import static java.time.ZoneOffset.UTC`
  - `ZonedDateTime.now(zone)`
  - `LocalDate.now(ZONE)`
  - `Calendar.getInstance()`
  - `new GregorianCalendar()`
- §5.1 requires the guard to fail on "any `.now(ZoneOffset…)`/`.now(ZoneId…)`". A later slice could reintroduce a business "today" that tests cannot move, and the build would stay green.
- The main code is clean today, so this is only a weakness in the guard.
- **Fix:**
  - Flag every `\b(Instant|LocalDate|…|MonthDay)\s*\.\s*now\s*\(` whose argument is not a clock expression. The simplest rule is to allow only `now(clock…)`, `now(AppClock.get())` and `now(WallClock.UTC)`, and flag the rest.
  - Add `Calendar.getInstance(` and `new GregorianCalendar(` to the list.
  - Extend `theGuardRecognisesEveryWayOfReadingTheSystemClock` with these lines.
